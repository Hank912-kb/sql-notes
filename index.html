1. SQL 語言總覽

🌍 什麼時候會用到：不管是網站後台、App，還是公司內部系統，只要背後有資料庫，開發者跟資料分析師幾乎每天都在寫 SQL — 從查會員資料、產生報表，到修改商品庫存，都要靠它。

SQL（結構化查詢語言）由 IBM 在 1970 年代初期定義，最早叫做 SEQUEL，第一個實作是 IBM 的 System R，1986 年成為 ANSI/ISO 標準。它是一種宣告式、以指令為單位的語言，幾乎所有關聯式資料庫都在用。

2. 資料定義語言 DDL — CREATE / ALTER / DROP TABLE

🌍 什麼時候會用到：工程師要上線一個新功能（例如「願望清單」）之前，通常要先用 CREATE TABLE 設計一張新的資料表來存放這個功能的資料；日後需求變了要加欄位，就用 ALTER TABLE。

DDL 語句用來定義資料表的結構：有哪些欄位、每個欄位是什麼型別、有什麼限制條件。

CREATE TABLE DEPARTMENT( name VARCHAR(50) NOT NULL, code CHAR(5) NOT NULL, total_staff_number DECIMAL(2) NOT NULL, chair VARCHAR(50) NULL, budget DECIMAL(9,1) NOT NULL, CONSTRAINT dept_pkey PRIMARY KEY(name), CONSTRAINT dept_ckey1 UNIQUE(code) );

常見的欄位型別：VARCHAR(size) 變動長度字串、CHAR(size) 固定長度字串、INTEGER 整數、DECIMAL(M,D) 精確位數的數字、DATE / TIME / DATETIME 日期時間。

第二張表加上 FOREIGN KEY，讓它的每一列只能參照真的存在的系名稱 — ON DELETE CASCADE 則代表刪掉一個系時，這個系開的課也會自動被一起刪掉。

CREATE TABLE COURSE( cnum CHAR(7) NOT NULL, title VARCHAR(200) NOT NULL, credits DECIMAL(2) NOT NULL, offered_by VARCHAR(50) NULL, CONSTRAINT course_pkey PRIMARY KEY(cnum), CONSTRAINT course_check1 CHECK (credits IN (6, 12)), CONSTRAINT course_fkey1 FOREIGN KEY(offered_by) REFERENCES DEPARTMENT(name) ON DELETE CASCADE );
常見錯誤：DROP TABLE 的順序錯了 — 因為 COURSE 有一個外鍵指向 DEPARTMENT，MySQL 會拒絕先刪 DEPARTMENT：
DROP TABLE DEPARTMENT; -- ERROR 1217 (23000): Cannot delete or update a parent -- row: a foreign key constraint fails DROP TABLE COURSE; DROP TABLE DEPARTMENT; -- this order works: drop the child table (COURSE) first

ALTER TABLE 用來變更既有資料表的定義：新增或刪除欄位、改型別、新增或刪除限制條件、幫資料表改名。DROP TABLE 則會把整張表連同資料一起永久刪除。

ALTER TABLE DEPARTMENT ADD COLUMN category VARCHAR(20); ALTER TABLE DEPARTMENT DROP COLUMN budget; ALTER TABLE DEPARTMENT MODIFY code CHAR(6) NOT NULL; ALTER TABLE DEPARTMENT ADD CONSTRAINT dept_check2 CHECK (code = UPPER(code)); ALTER TABLE COURSE DROP FOREIGN KEY course_fkey1; ALTER TABLE DEPARTMENT DROP PRIMARY KEY; ALTER TABLE DEPARTMENT RENAME TO NEWDEPARTMENT;

用 ALTER TABLE 加限制條件 — 最容易翻車的四個地方

假設 PAYMENT 資料表有一個 Fee（費用）欄位，規定「必須大於 0、且不超過 9999.99」。要把這個規則寫成限制條件，最容易在下面四個地方出錯：

① DECIMAL(p, s) 的精度算對

DECIMAL(p, s) 裡，p 是「總位數」、s 是「小數位數」，所以整數部分能用的位數 = p − s。要存 9999.99（整數 4 位＋小數 2 位）就要寫 DECIMAL(6, 2)，不是 DECIMAL(4, 2)。

欄位型別整數位數（p − s）最大能存的值
DECIMAL(4,2)299.99
DECIMAL(6,2)49999.99
DECIMAL(9,1)899999999.9

最後一列就是本頁 DEPARTMENT.budget 的型別 — DECIMAL(9,1)。

✗ DECIMAL(4,2) 上限只到 99.99，9999.99 存不進去
ALTER TABLE PAYMENT MODIFY Fee DECIMAL(4,2) NOT NULL;
✓ DECIMAL(6,2)：整數 4 位＋小數 2 位
ALTER TABLE PAYMENT MODIFY Fee DECIMAL(6,2) NOT NULL;

② MODIFY 只能改欄位「型別」，不能寫條件式

MODIFY 是用來重新定義欄位的型別（以及 NULL / NOT NULL）。「大於 0 且小於等於某個值」這種是「條件」，要用 ADD CONSTRAINT 加一條 CHECK 限制。

✗ MODIFY 後面不能直接接條件式
ALTER TABLE PAYMENT MODIFY Fee > 0 AND Fee <= 9999.99;
✓ 型別交給 MODIFY，條件交給 ADD CONSTRAINT ... CHECK
ALTER TABLE PAYMENT MODIFY Fee DECIMAL(6,2) NOT NULL; ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (Fee > 0 AND Fee <= 9999.99);

③ CHECK 裡的條件要寫完整，包含欄位名

每一個比較都要有「比較的對象」：欄位名在左邊、接運算符號、再接數值。兩個比較之間用 AND（或 OR）連接，不是用逗號。

✗ 缺少比較對象，SQL 看不懂
ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (>0, <9999.99);
✓ 欄位名 ＋ 比較符號 ＋ 數值，再用 AND 連起來
ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (Fee > 0 AND Fee <= 9999.99);

④ 邊界判斷：「不超過 X」要用小於等於

「不超過 9999.99」代表 9999.99 本身也是合法的值。如果用嚴格的「小於」，剛好等於 9999.99 的合法資料會被誤擋掉。看到題目的說法時，照下表選符號：

題目說法符號X 本身合法嗎？
大於 X>不合法
至少 X>=合法
小於 X<不合法
不超過 X（最多 X）<=合法
✗ 用 < 會誤擋掉剛好等於 9999.99 的合法值
ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (Fee > 0 AND Fee < 9999.99);
✓ 不超過 → 小於等於 <=
ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (Fee > 0 AND Fee <= 9999.99);
全部合起來： 先用 MODIFY 把型別改對，確保欄位真的存得下 9999.99；再用一條 ADD CONSTRAINT ... CHECK 寫完整的條件。
ALTER TABLE PAYMENT MODIFY Fee DECIMAL(6,2) NOT NULL; ALTER TABLE PAYMENT ADD CONSTRAINT fee_range CHECK (Fee > 0 AND Fee <= 9999.99);

3. 資料操作語言 DML — INSERT / UPDATE / DELETE

🌍 什麼時候會用到：使用者在網站上「註冊帳號」，背後其實是執行一次 INSERT；「修改個人資料」是 UPDATE；「刪除一則留言」是 DELETE。你每天滑手機做的操作，幾乎都會變成某一句 DML。

INSERT 新增一列，UPDATE 修改符合條件的列，DELETE 刪除符合條件的列。這三個在 COMMIT 之前都能用 ROLLBACK 復原 — 但它們都不會把資料表本身刪掉。

DELETE — 幾種挑列的方式

DELETE FROM COURSE WHERE cnum = 'CSCI235'; DELETE FROM COURSE WHERE (credits = 12) OR (UPPER(title) LIKE '%DATABASE%'); DELETE FROM DEPARTMENT WHERE total_staff_number < 5; DELETE FROM DEPARTMENT;

最後一行 — 沒有 WHERE 的 DELETE — 會刪掉每一列，但表本身還在（這跟把整張表刪掉的 DROP TABLE 不一樣，也跟速度更快、但不能 ROLLBACK 的 TRUNCATE 不一樣）。

常見錯誤：DELETE 的順序錯了 — 刪除一個還有課程的系會失敗，除非外鍵有宣告 ON DELETE CASCADE：
DELETE FROM DEPARTMENT WHERE name = 'Physics'; -- ERROR 1451 (23000): Cannot delete or update a parent -- row: a foreign key constraint fails DELETE FROM COURSE WHERE offered_by = 'Physics'; DELETE FROM DEPARTMENT WHERE name = 'Physics'; -- this order works: delete the child rows (COURSE) first

INSERT — 有沒有指定欄位清單

INSERT INTO DEPARTMENT VALUES ('Computer Science', 'CSCI', 30, 'Peter', 123456.9); INSERT INTO DEPARTMENT(name, code, chair, budget, total_staff_number) VALUES ('Mathematics', 'MATH', NULL, 12345.6, 10);
不指定欄位清單的 INSERT，值的順序必須跟資料表欄位順序完全一樣。明確列出欄位清單 — INSERT INTO T(col1,col2) VALUES(...) — 就可以跳過某些欄位（會變成 NULL）或改變順序。
常見錯誤：INSERT 的順序錯了 — 在系所還不存在之前先插入它的課，會違反外鍵檢查：
INSERT INTO COURSE VALUES ('PHYS999', 'Relativity II', 6, 'Physics'); -- ERROR 1452 (23000): Cannot add or update a child row: -- a foreign key constraint fails -- (fix: insert the 'Physics' department row first)

UPDATE — 改一欄、改好幾欄，或整張表都改

UPDATE COURSE SET credits = 12 WHERE cnum IN ('CSCI235', 'CSCI205', 'CSCI203'); UPDATE DEPARTMENT SET chair = 'Margaret', total_staff_number = total_staff_number + 1 WHERE name = 'Physics'; UPDATE DEPARTMENT SET total_staff_number = total_staff_number + 2;

SET 可以一次改好幾個欄位，中間用逗號隔開。跟 DELETE 一樣，沒有 WHERE 的 UPDATE 會套用到「每一列」— 這裡是讓每個系的教職員人數都 +2。

常見錯誤：改掉一個被其他列參照的值 — 把還有課程指向它的系改名，會用同樣的方式失敗，除非外鍵有宣告 ON UPDATE CASCADE：
UPDATE DEPARTMENT SET name = 'IT' WHERE name = 'Physics'; -- ERROR 1451 (23000): Cannot delete or update a parent -- row: a foreign key constraint fails
這個迷你引擎的限制：真正的 MySQL 會拒絕上面違反外鍵限制的 INSERT/DELETE/UPDATE，並顯示這樣的錯誤訊息。這個沙盒不會檢查外鍵，所以語句一定會被接受 — 上面用靜態範例呈現，這樣還是看得到真正的資料庫會回報什麼。

4. 語法骨架 — 先背順序，再談內容

SELECT 敘述的子句永遠照這個順序排列，這個順序不能亂，也是新手最容易寫錯的地方：

SELECT 欄位 FROM 資料表 WHERE 篩選單一列的條件 GROUP BY 分組欄位 HAVING 篩選整組的條件 ORDER BY 排序欄位;

記憶方式：先決定資料從哪來(FROM)，再篩選單一列(WHERE)，然後分組(GROUP BY)，對整組再篩一次(HAVING)，最後才排序(ORDER BY)。

常見錯誤：把 WHERE 寫在 GROUP BY 後面，或用 WHERE 篩選 COUNT(*) 這種聚合結果 — WHERE 只能篩「原始的一列」，篩「整組」要用 HAVING。

怎麼選？只用一次、只有一層 → inline view。同一句查詢裡要拆成好幾步、或同一段要重複用 → WITH。很多查詢都會用到、或要讓別人直接拿去用（甚至只開放看 view、不開放底下的資料表）→ CREATE VIEW。

17. 進階 DDL / DML

🌍 什麼時候會用到：季末要把「這一季的訂單」全部封存到另一張歷史資料表，可以用 CREATE TABLE ... AS 或 INSERT INTO ... SELECT 一次搬過去；清空一張「暫存匯入資料」的表格，用 TRUNCATE 比一筆一筆 DELETE 快得多。

這一章把前面學的 DDL / DML 跟 SELECT 子查詢接在一起：把「查詢結果直接寫進資料表」（CREATE TABLE ... AS、INSERT ... SELECT）、把「查詢結果當成刪除 / 更新的條件或新值」（DELETE、UPDATE 裡的子查詢），再加上一個快速清空資料表的 TRUNCATE。

語句類別子查詢用在哪能 ROLLBACK 嗎？
TRUNCATE TABLEDDL—不能
CREATE TABLE ... AS (SELECT ...)DDL新表的全部內容不能
INSERT INTO ... (SELECT ...)DML要寫入的那些列能（COMMIT 之前）
DELETE ... WHERE (子查詢)DML條件能（COMMIT 之前）
UPDATE ... SET / WHERE (子查詢)DML新值、條件，或兩者能（COMMIT 之前）
「能不能 ROLLBACK」就是 DDL 和 DML 最實用的分界線：DML 做錯了，COMMIT 之前還能反悔；DDL 一執行就是永久的。所以對 DDL 出手前要更謹慎。
